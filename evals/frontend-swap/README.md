# Frontend swap DEV proof

Run only in canonical after lane 4 has wired the consumer and scheduler. This fixture prepares three signed copies of the actual built frontend. It never starts a server or mutates production. A separate Team DEV utility shell serves the prepared directory and configures `FrontendBundles::open` with its test key and `allow_loopback=true` in a debug binary. Production trust remains unset.

1. Prepare with `node evals/frontend-swap/prepare.mjs dist /tmp/frontend-swap-fixture http://127.0.0.1:8769`. Discovery URLs are `/good/frontend-manifest.json`, `/incompatible/frontend-manifest.json` and `/broken/frontend-manifest.json` on that fixture origin. Change discovery only through the canonical DEV lifecycle constructor, then trigger the same scheduler event used by automatic checks.
2. Start agents mid-turn in the existing DEV instance. Record the listener PID and OS process start time; capture every PTY ID and every tab's exact bound session ID with `dc tab inspect ID --json`. Record tabs, workspaces, exact draft text, attachment IDs, both scroll anchors and DOM/version. All CLI calls in this bench must use `dc` after sourcing `evals/_lib/lib.sh`.
3. `bash evals/frontend-swap/capture.sh /tmp/frontend-swap-before CLIENT_ID` records daemon health, frontend state, the complete daemon checkpoint, tabs and workspaces. Keep the identity and DOM observations beside those files.
4. Hold an open modal or typing/composition signal. Publish the good fixture to discovery. A ready SSE event must leave the old DOM mounted. Close the modal, stop composing and emit explicit idle/focus safety. Require a checkpoint read-back containing the very last edit, the good fixture's visible `Frontend fixture version` output, and restored active tab/draft/attachments/scroll in the actual app. Capture the after state and compare PID/start time, PTYs and bound sessions exactly. No submitted draft or PTY input is allowed.
5. Publish incompatible discovery. The active index and DOM must stay on the good version; no request may load incompatible assets.
6. Publish broken discovery. Its exception is observed by `/frontend/bootstrap.js` before candidate scripts. Require automatic previous-version navigation and stable restored app DOM, with the same agents continuing their original turns. Check the quarantine and bounded retry state. Repeat with a missing root signal and then a failing previous bundle to prove compatible bundled recovery.

An HTTP 200, ready SSE or active pointer alone is insufficient. Save before/after DOM observations and exact backend identities. Live proof remains a canonical gate; fixture preparation tests prove only signing and archive construction.

Consumer integration: register `frontend_bundle`, `frontend_bundle_api_version` and the API route module; merge `frontend_bundle_routes::router(app_state.clone(), bundles)` below the existing bearer middleware. Startup/scheduler callbacks run `check()` on a blocking worker. Feed a bounded failure event to `failure_deadline(now_ms)`; it never reports success. Use `active_index()` for initial immutable navigation and a compatible served bundled index when absent. All pointer changes are one SQLite transaction; retain release directories while pages reference them (this implementation conservatively retains all releases).

Client integration: `createFrontendUpdateClient(http, clientId)`, `initialSwapState(api, checkpoint, safety, persistedRevision)`, and `createSwapController`. Feed explicit ready/safety/edit/rollback events. Hydrate the checkpoint before render, preserving attachments and scroll. The reload callback calls `preparePageReload` with explicit daemon origin/auth, client ID, health ticket and bundled API range. Dispatch `codeterm:frontend-root-rendered` with exact releaseId/generation only after root render. Desktop also needs the independent native observer owned by lane 4. Tokens stay in origin session storage and authenticated RPC bodies; SSE status omits claims.
