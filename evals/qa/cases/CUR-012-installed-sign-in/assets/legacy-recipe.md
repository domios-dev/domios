## Steps and far-end evidence

1. For an explicit prod account grant only, read `GET http://127.0.0.1:7685/api/health` with credentials in memory; record build/version. Capture `codeterm account status --json` in memory and emit only provider, pending and identity presence. Expect Firebase and the authorized initial state. Do not use DEV tools against prod.
2. Start Sign in once from the real app Account menu. If using the installed daemon's web mirror, name that surface honestly; it does not separately prove a native desktop click. The app owns state, verifier and allocated callback. Do not fabricate a challenge to obtain an app PASS.
3. Read the newly opened URL in memory. Require HTTPS host `domios-d9357.web.app`, path `/signin/`, exactly one nonempty state and code_challenge, and redirect_uri equal to `domios://auth/callback` or `http://127.0.0.1:<allocated-port>/callback`. Emit booleans/lengths only. No `localhost` or foreign callback. If transferring into an owned Domios Browser, navigate over its CDP in process memory, never `goto "$SECRET_URL"` argv. Do not modify challenge fields.
4. Snapshot/action/snapshot with query and page-title redaction. Expect Email address, Password, Sign in and Use an email sign-in link instead. If absent or request invalid, stop and inspect a redacted screenshot. CAPTCHA/consent/2FA are human prerequisites, not a reason to disable AppCheck.
5. If granted, submit one deliberately wrong password without exposing either value; require a recoverable error and no callback/code/session. Then use the genuine QA password, preserving the same supported UI flow. Values enter only the live form from secret-store process memory. Avoid screenshots while credentials or challenge chrome are visible. Never substitute Firebase REST login, SDK injection or custom-token seeding.
6. Let the hosted AppCheck/createDesktopLoginCode/PKCE/redeem path finish. Verify actual account pending=false, provider=Firebase, and intended UID equality computed in memory (`same_uid=true`). Verify signed-in Account identity/plan UI with identity redacted. A free plan or HTTP200 alone fails this oracle.
7. Reload only the authorized view and require UI continuity. Credential recovery needs an Elgar-owned full app restart, new boot proof and the same UID after refresh; a frontend reload cannot pass that subcase. Never kill prod.
8. Sign out only the QA session through UI or documented `codeterm account logout`; require identity=null and pending=false, and signed-out Account UI. Close only own Browser/system sign-in tabs. Retain QA user/password entries; do not wipe stores or change entitlements.
