# Codex update and runtime handoff — core when updater/runtime restart changes

Purpose: prove a real installed binary update, visible updater output, automatic runtime migration, and exact-session input preservation.

Preconditions: parent grants the machine-global update, every competing QA owner releases its boundary, DEV health matches the supplied SHA/boot, registry offers the intended newer version, and the loaded provider version is verified with `dc plugin list`. Use only `evals/_lib/lib.sh` wrappers. Never downgrade the machine binary to manufacture another run.

Fixtures: spawn an owned idle Codex tab and a separate owned busy Codex tab in the QA workspace. The busy turn executes a Node helper that creates a ready marker after installing an fs.watch listener and waits for an exact run-unique release filename. Its agent must retain and await the process handle, then emit one unique done marker. The idle tab emits one ready marker. No sleeps. Record fixture ids, claimed session ids, binding nonces, state, epoch and `agent_runtime_state.binaryVersion` immediately before clicking. Require idle ready and busy working plus ready-file evidence.

Steps: open the idle tab through the owned Browser, snapshot, identify its composer `Provider CLI update` group, and click its Update button once. Capture the visible utility job, progress state, job terminal output and eventual result. Read `dc agent cli status codex --json`; a successful command alone is insufficient: detected_version and the restarted idle runtime must both equal the target. While the busy gate is still closed, capture idle new version and busy old version/working with unchanged claimed sessions. Then create the owned release file once, wait for the exact assistant done article, and capture both runtimes again. Count actual own-session user/tool/assistant rows through `dc tab chat --tab <fixture> --json`; do not accept a text wait that merely matches the user's instruction.

Evidence and verdict: PASS requires visible job/progress/result, actual target version, idle migration without manual restart, deferred busy migration after its tool/turn completes, original sessions and no duplicated/lost input. If a real restart fails, inspect the scoped `[provider-runtime-update]` debug events to prove at most one automatic recovery and its actual outcome. Epoch deltas alone do not count restart attempts. FAIL an actual updater/runtime failure; downstream handoff is NOT RUN if the binary update failed. A source/unit-test report is separate from this live proof.

Pitfalls from executed runs: c07's inherited Git tar parsed Windows C: as a remote host, updater exit1 and binary stayed0.162.1; never replay Update to repair the environment. On5274 the System32 tar prefix produced a real0.162.1to0.163.0 update. Idle first restart hit a Codex sqlite initialization failure, followed by exactly one successful automatic recovery, proven by recovery=false/failed=true then recovery=true/failed=false; busy migration succeeded normally after release. Old fixture command restrictions survive restores, so recreate rather than repurpose a wait-only agent for a different test. Native screenshot/DOM may omit status copy from accessibility; inspect screenshots and retain CLI/job evidence together.

Cleanup: await gated process exit before closing the owned idle/busy/job tabs; remove only the exact owned ready/release/helper files. Preserve evidence in the pad/catalogue. Never close unrelated tabs, restart prod, or manually install the binary as a substitute for the click journey.
