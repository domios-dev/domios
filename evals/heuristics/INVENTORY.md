## Connected decision contract

For an event-level classification, a connected decision model's valid verdict at confidence >=0.60 and not `other` decides; the heuristic runs only on no adapter, timeout, error, budget, `other` or low confidence. Each decision writes a unique `observation_id` and `decided_by: adapter | heuristic | fallback(<reason>)`, with reasons `no_adapter`, `timeout`, `error`, `budget`, `other`, `low_confidence`. Unsupported primitives and connection errors abstain. D actions proceed on deterministic evidence without a model gate.

F: confidence <0.60 abstains. N: >=0.80 may notify, normally after two distinct agreeing event observations in one episode; authoritative baseline prompts/errors remain immediately visible. A: a new automatic response needs >=0.90 on the minimum component confidence, two distinct agreeing event observations, a qualification receipt and all local deterministic authorization. Questions within one request are not distinct observations. A model never invents keys, trust entitlement, permission policy, session binding, success, reset timestamps or process death.

One envelope carries the redacted bounded current frame and minimal context to at most six named questions. Identity stays local: tab, PTY, session/launch nonce, generation, frame and occurrence. One action owner coordinates trust, update, permission and Supporter ledgers. Revalidate generation, prompt identity, frame, PTY and policy immediately before action. Disappearance, contradiction, disconnect, user response, identity change or budget depletion invalidates pending automation. No adapter means the literal baseline path, without added screen reads, workers, reservations, pending state, suppression or notifications.

Concurrency contract for the implementation: four global in-flight observations, one per tab, a 32-event queue coalescing superseded noncritical frames, stale work dropped, owner input retained. No sleeps, polling, locks across model calls, or waits on delivery/output/readiness/exit. No default hourly request cap; optional configured caps apply. Count physical requests at the real transport boundary, including errors; a method invocation is not evidence of a physical call. Single-request observations require an explicit adapter batch capability.

## Questions

Minimal model state M: redacted current rendered tail, bounded to 40 lines and 8 KiB; terminal dimensions/cursor/alternate-screen context; provider capability bits; event and candidate provenance; pending kind and explicit-vs-scraped source; launch-authenticated boolean; role; provider process observation with evidence source. Raw credentials, tokens, codes, URL query secrets, unrelated sessions and full transcripts are excluded. Options appear only when needed. Hashes, exact cwd, binding/nonce, PTY and action handles stay local. A truncated option set cannot authorize automation.
