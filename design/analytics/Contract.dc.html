Plugin boundary and data contract

What task_rli26s (the host capability) and task_w1du4w (the core plugin) build from this design. Field and call names marked proposed may be renamed by the host task; the meanings may not.

What Analytics is, and isn't

It isIt isn't
Totals over a range for this machine: new input, generated, read from cache, turns, and tabs created.A feed of plan events, verdicts or decisions. Those stay on each team's Board, and the view only links there.
A breakdown by provider and model, workspace, team or plan, and a chart over time.A cost report. No prices are applied; money is always “not recorded”.
The allowance each provider account reports, shown for the whole account.Allowance per model, workspace, team or plan. That attribution does not exist and is never estimated.
This machine only.A mesh-wide rollup. Other machines' ledgers are not read.

The core plugin

AspectDecision
Identityid: "analytics", shipped in the embedded codeterm-core channel as a trusted system plugin, enabled by default. The user can disable it in Plugins; the titlebar button then goes away.
Manifestcapabilities.view: true (sandboxed ui/ iframe). permissions empty: no subprocess, network or secrets.
Where it rendersIn a new analytics main view that sits beside settings, memory, mesh and extensions. It is not the tab-owned pluginViewId overlay, which closes when the active tab changes.
Data accessOnly through the host capability below. The plugin never opens kpi_ledger.db, usage.db or a SQLite handle, and never parses provider session files.
Provider neutralityNo branch on a provider or model id, in the plugin or in core. Provider and model are opaque strings from the data; the chart colour comes from each key's order, never from its name.
ThemeUses --ct-* tokens only, so github-light and the other built-in themes follow. These frames show the default github-dark.

Query · proposed analytics.query

AnalyticsQuery {
  range:    { from: "2026-09-09", to: "2026-09-15", tz: "Europe/Riga" }  // local calendar days, inclusive; at most 92 days
  bucket:   "day" | "week"          // day up to 31 days, week beyond, at every width
  filters:  { providers?: string[], models?: ModelKey[], workspaces?: string[], teams?: string[], plans?: string[] }
  group_by: "provider_model" | "workspace" | "team" | "plan"
}
ModelKey = { provider: string, model: string | null }   // null selects "Model not reported" for that provider

Within one filter group choices widen (OR); across groups they narrow (AND). A null id is a selectable key in every group.

Providerprovider, always present—
Modelmodelnull becomes “Model not reported”, kept under its own provider and never guessed from the provider's current default.
Planplan_idnull becomes “No plan”, a real bucket. An id with no plan record becomes “Deleted plan · id”.
TeamThe plan's team_idNo plan, or a plan without a team, becomes “No team”. No team identity is invented.
WorkspaceRequires a new field: the workspace the event's tab belonged to, recorded when the event is writtenRows written before the field exist are “Workspace not recorded”. They are never back-filled from where the tab lives now, because tabs move and close.
Tabs createdRequires a new record made when a tab is created, with its kindEverything before that record exists is not_counted. spawn events count agent launches, restores included, and are never relabelled as tabs.
AllowanceLatest parsed usage_snapshots row per provider accountNo snapshot: “hasn't reported allowance”. Older than the provider's telemetry age: stale: true, shown as “may be out of date”.
MoneyNothingAlways not_recorded. A provider's spend_cents may be shown later as account-level only, under a separate approval.

Coverage, zero and colour

not_recordedThe bucket is before first_recorded_at, or recording was off. Drawn hatched, with no value and no tooltip figure.
partialRecording began or stopped inside the bucket. Drawn normally, with the boundary time under the label (“from 17:50”).
recorded, 0Recording covered the whole bucket and nothing happened. Drawn as a 2px baseline stub labelled 0.
ColourThe first four keys, ordered by their total over the unfiltered range, take --ct-accent, --ct-magenta, --ct-cyan and --ct-green as on the Board's spend chart. The rest fold into a grey Other. Null buckets are hatched grey. Filtering never repaints a key that stays visible.

Read path

The host answers from a bounded, cached read model that is rebuilt when the ledger gets new rows, not on every open. Nothing is aggregated on the Tauri async runtime or on a tab-switch path. The plugin re-queries on open, on a filter change and on Refresh, and never on a timer.

Out of scope for 1.10.20

Money and prices; mesh-wide totals; per-model allowance; exports; the Board's Spend, Models and Needs you cards (unchanged); the plan event log; any change to PTY or Chat delivery.
