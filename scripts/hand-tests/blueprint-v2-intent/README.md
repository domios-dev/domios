# Native intent authoring proof

Chair owns setup, DEV lifecycle and all three provider-native launches. Workers author this harness. Final live delivery requires PASS on the clean integration SHA; neither the offline checks nor simulated effects clear it.

1. Real-merge accepted call, BLU-41 main/envelope runtime, BLU-44 ordinary-process runtime/budgets and isolated DEV fixes. Create a new output directory outside all author cwds. Copy `chair.example.json` to `OUT/chair.json` and fill actual full prerequisite SHAs and provider binary/model identities. Fill isolated DEV Team/workspace/tab ids after launch in step 4. All four CLI actor tabs must be in that named DEV Team with cwds under OUT. They are CLI principals only; headless author session identities are independently recorded. No prod selectors or production state are used.
2. Before starting DEV, run `CODETERM_INSTANCE=blueprint-v2-proof CODETERM_API_PORT=17693 bash scripts/hand-tests/blueprint-v2-intent.sh --prepare-launch --out OUT`. This binds the chosen port once and refuses a busy port. It records the clean SHA/free-port receipt and launches nothing. Never delete/rewrite an existing receipt to retry.
3. In Chair's DEV utility shell run exactly `CODETERM_DEV_INSTANCE=blueprint-v2-proof CODETERM_DEV_API_PORT=17693 ./build.sh dev --wait`, preserving its complete stdout/stderr in `OUT/launch.log`. The accepted isolated DEV launcher must be an ancestor of the tested SHA. A different port, headless-only server, stale build or absent authenticated native client refuses.
4. Provision the isolated Team/CLI actor identities using supported DEV commands through `evals/_lib/lib.sh` helpers. The Orchestrator actor must have keep authority. This may be done on the already-running matching named DEV before the final invocation; it never launches a model author. Subject actor tabs may be plain QA shells. Update only the external Chair receipt, never source. Verify actual identities and provider availability before the one live invocation.
5. From the clean integrated checkout run once:

```bash
CODETERM_INSTANCE=blueprint-v2-proof CODETERM_API_PORT=17693 bash scripts/hand-tests/blueprint-v2-intent.sh --out /Users/dev/.domios/runtime/agent-pads/f110fd04/blueprint-v2-live
```

The harness refuses a second invocation, source/health/CLI prompt mismatch, missing prerequisite ancestry, unsupported clean provider launch, extra context, stale native attachment, false reuse or wrong/missing effect. It creates no Domios child agents and restarts nothing. Each required case has one fresh bounded 900-second headless session; a refusal stays in the denominator. Cases are fresh Codex gpt-6.1-sol/high and Claude positives plus one fresh Codex no-fit author. Claude uses safe mode, Bash only, no settings/MCP/skills/session persistence. Codex ignores user config/rules/project docs, disables memories/plugins/hooks/other agent capabilities and uses the provider's workspace-write author policy at its empty trial cwd. Exact current CLI help, argv, environment key names, cwd listing, prompts and hashes, full redacted output/error streams, sessions and usage are retained. The only initial CODETERM keys are DEV_INSTANCE and DEV_API_PORT. Every subject invokes a helper-backed `domios`/`codeterm` proxy; identify is first proved inside that scrubbed environment. No token is passed to a model process.

Each Blueprint code or command step runs with the user's own permissions, like an agent in a tab, without Domios credentials in its environment; foreign Blueprints are gated by folder trust (1.15.4). These execution rules are separate from the provider author's launch policy.

The exact delivered prompt is the actual QA CLI's `docs BLUEPRINT-AUTHORING` bytes, required to match the source hash in `prompt-decision.json`, followed by `\n\nTask\n\n`, the formatted task from `tasks.json`, and one newline. No mem preamble, coached call example beyond the shipped cookbook, gold fact or checkout context is added. Expected 73 stays outside author cwds/input. The sink script knows no expected value. No-fit fully specifies 5+6 -> 11; actual returned candidates are recorded and may be irrelevant, but no call reuse is allowed.

Before author launches the real product applies and executes the stored calibration code to an isolated fixed stdin sink, then `keep --file` persists its typed callable. Vector/enrichment readiness is observed using authenticated SSE plus named-DEV memory WAL file events, subscribed before mutation; conditions are inspected only initially/on events, with 180-second deadlines and 128-read bounds. Sink completion is likewise event-driven. No sleep, timer polling, search-result forcing or model retry exists.

Each author writes `authored.json`, captures the real check response in `checked.json` and saves its exact returned `definition` in `sealed.json`. The harness verifies discovered mem id/hash, typed call arguments and retained dependency closure, then actually applies that same checked file. PASS requires executed code-node journal evidence, retained id/hash and expanded code through `show`, completed real run records and sink integer 73 for each positive. No-fit must check and execute to 11 with zero calls/dependencies. Full CLI responses, graphs, native/health/source proof, candidates, effects and per-author outcomes remain under OUT. The catalog qualification cases run on macOS, Linux and Windows; their Rust execution proofs run on ubunta through Chair, with Windows DEV covered by Elgar. The live harness records the actual tested platform and names other platforms without a live receipt as unverified. Failed runs are preserved for diagnosis; cleanup and any new run require Chair's decision.

Shell syntax: `bash -n scripts/hand-tests/blueprint-v2-intent.sh scripts/hand-tests/blueprint-v2-intent/transport.sh`. Live authoring requires the real delivery evidence described above.
