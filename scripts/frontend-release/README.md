# Independent frontend release

`frontend-release-contract.json` owns frontend version 1.0.0 and API range 2..2 independently of app versions. Increment its version before a new `frontend-vX.Y.Z` release. Contract version 1 uses exactly six manifest fields, sorted compact UTF-8 JSON without a newline. SHA256 covers the archive. Detached default prehashed minisign (`ED`, Ed25519 over BLAKE2b-512) covers the entire manifest. Format reference: https://jedisct1.github.io/minisign/.

Archive entries are UTF-8 byte sorted regular files, USTAR, mode 0644, uid/gid/mtime zero, no owner names, gzip level 9 without wall-clock metadata. Symlinks and nonregular files are refused. Entries have no wrapping dist directory. Paths longer than 100 UTF-8 bytes are refused explicitly.

Fixtures: `fixtures/frontend-test.pub`, `frontend-test.pem`, `frontend-manifest.json`, `frontend-manifest.json.minisig`, `frontend-v1.0.0.tar.gz`, and `dist/`. This is an intentionally public TEST ONLY key pair. Runtime tests inject this public key; production must never bake it in. The committed archive contains index.html and assets/fixture.js. Producer verification uses Node crypto; the consumer's independent minisign-verify implementation must also accept the fixture after merge.

Production is disabled until the owner provisions a distinct frontend minisign key, reviews its public key in both this contract and baked daemon/app constants, installs minisign on linux-build, protects the frontend-signing and frontend-publication environments with owner approval and trusted refs, and sets FRONTEND_SIGNING_PRIVATE_KEY and FRONTEND_PUBLICATION_TOKEN in their respective environments. The secret is an unencrypted minisign key protected by the GitHub environment; it is passed via environment, written to a mode-0600 temporary file, never put in argv or logs, and deleted in finally. The publication token needs only Contents write on rollacode/codeterm-releases. Neither job uses the app updater key. Build has only source Contents read; publication has no signing secret.

The owner must create the separate frontend-latest discovery release once with latest=false; it must not change app latest. Publication creates a new version draft, uploads all immutable assets without clobber, reads each asset back byte-for-byte, publishes with latest=false, then updates the discovery manifest and detached signature. Old versioned releases remain downloadable. Partial failures leave an unpublished draft for owner review; reruns refuse existing versions. Discovery asset pair replacement is not atomic on GitHub: during replacement a verifier can see mismatched bytes and must fail closed, retaining its active bundle. A discovery failure after version publication leaves the old discovery available; recovery updates discovery only after re-verifying complete version assets. No version asset is overwritten.

Dry run: `gh workflow run frontend-release.yml --ref release/1.14.2 -f dry_run=true -f tag=frontend-v1.0.0` after integration and workflow registration. This uses the fixture identity, a read-only token, and only uploads an Actions artifact containing dist/index/assets, archive, canonical manifest, signature, verification key and provenance. Production jobs are skipped. Review logs for only ./build.sh frontend (TypeScript/Vite), no CLI/Rust/app build. Download the artifact and verify with the lane 5 verifier or `minisign -V -H -m frontend-manifest.json -p frontend-verification.pub`. Also recompute archive SHA256 and extract index/assets. No public release/tag action is authorized in a lane.

Focused gate: `node --test scripts/frontend-release/*.test.mjs`. No Rust selectors apply to this producer lane. Rollback the lane merge to remove the workflow/producer; published archives remain immutable. Roll back runtime via lane 5 release pointers separately.
