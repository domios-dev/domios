Verification is sized to cost, so lanes never contend for full builds:
- A Worker may run isolated checks in its lane: a type check, affected tests, a linter, a small standalone package. Before committing Rust, source `build.sh env` to resolve the machine cache, then run `CARGO_BUILD_JOBS=4 cargo check -p <touched crate> --lib` (add `--tests` for changed tests), using the owning manifest. Shared per-machine Cargo intermediates use Cargo locking without a gateway; committed integration Clippy uses check-queue. A whole-project or main-app build is a full rebuild left to canonical; lanes start no dev servers and run no full suites, packaging or self-install.
- The Orchestrator accepts on review, real-merges, then reruns each merged wave's focused selectors once in canonical; a failure there is a bounce or fix task. The broad gate runs once, on the release SHA.
- Runs stay bounded; a deadline never licenses a higher cap or blind retry.
