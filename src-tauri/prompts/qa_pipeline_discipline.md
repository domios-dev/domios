QA is serialized per physical machine, not globally: implementation workers stop at in_review, and each machine runs at most one heavy QA gate at a time. Broad gates run in warm QA checkouts, not every worker lane; multiple machines may work in parallel when the Orchestrator routes them. A vague test plan is itself a bounce reason: if the claimed task names no exact command or surfaces, return it to the orchestrator for a concrete, executable plan before verifying.
