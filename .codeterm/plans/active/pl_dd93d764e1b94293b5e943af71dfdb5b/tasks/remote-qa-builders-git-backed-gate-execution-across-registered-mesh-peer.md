DESIGN (Planner, round-75, user intent: ROG/eight/ubunta act as registered BUILDER machines through git — orchestrator queues gates for refs, peers execute in their own warm checkouts, one gate at a time per machine, structured results back; ordinary workers never run heavy gates anywhere). FEDERATES the local one-QA-per-machine registry (task_5a6d58c5 — its per-daemon QA-pane registry is the LOCAL primitive; this task makes registered peers addressable as remote QA targets). PRODUCT-GENERAL THROUGHOUT: no machine names, no repo paths, no branch names in code — peers, remotes, and refs are all data. COMPONENTS: (1) BUILDER REGISTRATION: 'codeterm qa builder register [--label linux-x64] [--repo <remote-url-or-fingerprint>] [--checkout <path>]' run ON the builder machine — extends the 5a6d58c5 registry entry with builder capability + platform label + the warm checkout it owns; registry is per-daemon, gossiped over mesh presence so the orchestrator sees 'builders: ROG(win-x64), ubunta(linux-x64), eight(mac-arm)'; deregistration + liveness via existing mesh presence. (2) REF SEMANTICS (git-backed, the user's key constraint): gates are queued for a REF (branch name or exact sha) + repo identity fingerprint (normalized remote URL hash — a builder refuses refs for repos it does not host); builder execution = fetch the ref into ITS OWN warm checkout (git fetch origin <ref> && checkout --detach FETCH_HEAD — detached, never mutating local branches), verify sha matches the queued sha when one was pinned (push-then-queue race safety), refuse dirty checkout with the standard dirt-exclusions (task_4fc2ae89 coordination). (3) PER-MACHINE QUEUE: strictly serial per builder (the whole point — one heavy gate per machine at a time); queue entries: {task_id, plan_id, ref, sha, gate_spec (the task's GATES REQUESTED lines or explicit commands), requested_by, timeout}; timeout mandatory (capped-runner discipline inherited — a hung gate is a finding, not a wait). (4) CACHE REUSE: the warm checkout IS the cache (sccache/target reuse per machine — existing infra, document not rebuild); consecutive gates on the same repo reuse it; NO worktree-per-gate on builders (that reintroduces the multi-build contention this kills). (5) RESULT FORMAT (structured, machine-parseable): {gate, ref, sha, builder, platform, started/finished, exit_code, verdict pass|fail|timeout, per-suite counts where parseable, log tail (bounded), artifact paths optional} — lands as a STRIDE on the task (existing evidence channel) + report to the requesting orchestrator; failures carry the repro command verbatim. (6) INTEGRATION with plan qa: 'codeterm plan qa --task X --builder <label|peer>' (or --platform linux-x64 to auto-pick) enqueues remotely instead of locally — same command surface, the builder choice is a parameter; no builder registered for the platform -> honest refusal listing available builders. (7) SAFETY: builders execute ONLY registered gate specs from plan tasks (no arbitrary command channel beyond what mesh exec already permits — audit against the existing mesh security notes); refs must exist on the shared remote (no patch-shipping — git is the ONLY content channel, per user intent); worker panes on builder machines remain non-QA (the local registry still gates them). STAGING: phase 1 = registration + manual routed execution (replaces today's hand-driven eight/ROG runs); phase 2 = queue + auto-pick + result strides; phase 3 = watchdog integration (gate-running state visible on task cards via the lane observability chips). POST-RELEASE — the current release finishes on manually-driven QA runners; this makes that flow a product feature.
