DESIGN (Planner, at Orchestrator request after live dispatch friction — 4 manual commands per worker, mistakes on --parent, id formats, readback). ALL PRIMITIVES EXIST as separate flags (verified: agent spawn has --role/--parent/--plan/--task/--mesh/--workspace/--model/--cwd; plan task update has --status/--pane/--branch/--executor-role) — this command is COMPOSITION + ATOMICITY, not new capability. COMMAND: codeterm plan task dispatch <plan> <task> [--provider P] [--model M] [--role Worker] [--mesh PEER] [--cwd PATH] [--worktree auto] [--branch auto] [--read-only] [--gate] [--force] [--dry-run] [--json]. SEMANTICS, in order: (1) RESOLVE plan+task through the unified short-id resolver (never full-id-only); (2) DEFAULT ROUTING FROM THE TASK: tasks already carry routing model + why — --provider/--model default to the task's recorded routing, flags override; refuse (exit 2) if neither exists; (3) COMPOSE the worker prompt server-side from the task record, fixed order: role_guidance (opening stance) -> task name+body -> acceptance criteria -> test plan -> correctness vector -> loop/competitive context blocks if the task carries them (reuse existing WORKER_LOOP/COMPETITIVE consts) -> report contract with EXACT ids pre-filled ('when done: codeterm agent report --status in_review --plan <plan> --task <task> ...'); (4) WORKTREE MODE (--worktree auto, default for coding lanes, skipped with --read-only): create git worktree from current integration head, branch lane/<task-slug> (--branch auto derives, explicit overrides), print cleanup hint; --read-only spawns in the integration checkout with a read-only charter line prepended and NO branch/worktree; (5) SPAWN with --parent = calling pane (from CODETERM_PANE_ID), --workspace inherited unless --mesh; (6) ATOMIC ASSIGN: one daemon-side operation sets status=in_progress + pane + branch + executor history + records a dispatch stride (who/model/branch/worktree) — if spawn succeeded but assign fails, kill the spawned pane and exit non-zero with both errors printed (no half-dispatched state); (7) OUTPUT: last line is ALWAYS the machine-readable result (pane id, branch, worktree path) — no hint lines after it; --json full object; (8) --gate mode: for long-shell-gate lanes, print the completion-contract wrapper (TEXT D pattern) pre-filled with pane/task ids instead of spawning an agent; (9) --dry-run prints the fully composed prompt + planned mutations and exits — the debugging affordance for prompt assembly; (10) IDEMPOTENCY: task already has a live assigned pane -> refuse without --force (print the existing lane); --force records a reassignment stride. PROVIDER PREFERENCE: pure pass-through of provider/model — no hardcoded provider ranking in core (capability rule); the task's routing why is the preference mechanism. TESTS: unit for prompt composition order + routing default/override matrix + idempotency guard; e2e drill on dev: dispatch a dummy task, assert pane spawned with parent set, task in_progress with pane+branch, stride recorded, report round-trips; rollback path test (inject assign failure).
