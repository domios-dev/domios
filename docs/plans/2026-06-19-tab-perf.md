# Tab-Switching Performance — Plan (from Austen's audit)

> Source: Austen's perf audit (27 agents, 712 tool calls, full code read,
> high-confidence). Owner: Austen executes the perf tracks; orchestrator
> (Opus) gates + merges (pre-push hook clippy + tsc) and SEQUENCES against the
> chatBackend-parity (P-tracks) and preset-UX (D-tracks) to avoid file conflicts.

## Root causes (CRITICAL)
1. **Monolithic MultiplexerContext** — `src/store/multiplexer/context.tsx:33` +
   `index.tsx:499`: one context, value object never `useMemo`'d; every dispatch
   (status ticks, OSC titles, focus) re-renders ALL `useMultiplexer()` consumers
   (~3N+sidebar per tick). Reducers spread the whole state on hot paths
   (SET_FOCUSED_PANE, UPDATE_PANE_STATUS, SET_ACTIVE_TAB maps all workspaces,
   SET_PANE_TITLE spreads panes map). `memo(TabContent)` broken (new pane ref each SET_STATE).
2. **IPC round-trip per event** — `service/mod.rs:172` + `index.tsx:159`:
   `mux-state-changed` (~50ms) carries EMPTY payload → frontend `invoke(mux_get_state)`
   → Rust clones whole panes map O(N) + serializes → full round-trip every event.
   Fix: embed snapshot in the event payload.
3. **Tab activation replays ≤2MB + double PTY resize** — `usePtyConnection.ts:88`:
   replay full scrollback every show; two back-to-back resizes. Fix: screen-only on
   first mount, delta on remount; drop the redundant resize.

## High-priority
- `TerminalPane` no `React.memo` (TerminalPane.tsx:52) — all N panes re-render per ctx update.
- Tab click = TWO IPC calls → two state-changed → two storms (Sidebar.tsx:611, pane_routes.rs:492); merge into one atomic backend command.
- **WebGL renderer disabled on macOS/Windows** (useXterm.ts:20) — 2-line fix, biggest rendering gain.
- mux lock ~11×/PTY chunk in process_pty_output — Mutex→RwLock + hoist read snapshot.
- `chat_start` blocks async executor on full JSONL parse, no cap (commands/pane.rs:198) → detached tokio::spawn.
- 1500ms `get_pane_text` poll runs on ALL tabs incl hidden — gate to visible.

## Do NOT touch (confirmed correct)
Keep-alive opacity:0 tab swap; tab switch doesn't wait on QuickJS VM lock; async
host.exec job-id+poll (recent fix good); per-pane non-blocking PTY write queue;
chatBackend sessions survive tab switch (torn down only on close); no mem queries
on tab switch; the 50ms coalescing design (only the empty payload + 2nd IPC is the bug).

- **A2** `useMemo` context value + useCallback deps via `stateRef.current` (index.tsx:499). ⚠️ index.tsx overlaps my P2 (spawnAgentTab) — A2 lands BEFORE P2; P2 rebases.

- **A8** chat_start JSONL scan → detached tokio::spawn (commands/pane.rs:198). ⚠ pane.rs overlaps P1/P4 — sequence after they merge.
- **A9** MuxState Mutex→RwLock + hoist snapshot in process_pty_output.
- **A10** SET_ACTIVE_TAB structural sharing — active_tab_id as top-level Record<wsId,tabId>.
