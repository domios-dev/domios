### F. Socket JSON-RPC (socket/server prefix-routed dispatch)

Hit each domain prefix to verify routing:

```bash
# Token lives under [api] section in config.toml. jq doesn't parse TOML —
# extract it with awk instead. (yq would also work if installed.)
PORT=7686
TOK=$(awk -F'"' '/^token[[:space:]]*=/{print $2; exit}' ~/.codeterm-dev/config.toml)
curl -s -X POST localhost:$PORT/rpc -H "Authorization: Bearer $TOK" \
  -d '{"method":"workspace.list","id":1}'    # workspace.* domain
curl -s -X POST localhost:$PORT/rpc -H "Authorization: Bearer $TOK" \
  -d '{"method":"pane.list","id":1}'         # pane.* domain
curl -s -X POST localhost:$PORT/rpc -H "Authorization: Bearer $TOK" \
  -d '{"method":"notification.list","id":1}' # notification.*
curl -s -X POST localhost:$PORT/rpc -H "Authorization: Bearer $TOK" \
  -d '{"method":"agent.status","id":1}'      # agent.*
curl -s -X POST localhost:$PORT/rpc -H "Authorization: Bearer $TOK" \
  -d '{"method":"cron.list","id":1}'         # cron.*
curl -s -X POST localhost:$PORT/rpc -H "Authorization: Bearer $TOK" \
  -d '{"method":"bridge.status","id":1}'     # bridge.*
```

- [ ] Each returns `{"result":...,"id":1}` (no `JsonRpcError: method not found`)
- [ ] Unknown method `foo.bar` returns proper error code

## Failure protocol

If anything fails:
1. Capture stderr / log excerpt
2. Note which surface (split file likely involved)
3. Mesh-ping the other peer with the failure
4. Don't push fixes until both peers confirm the same failure
5. **Confirmed failure → file under `docs/release/1.1.9-issues.md`** with:
   - reproducer (commands / clicks)
   - which split surface is implicated
   - **classification: blocker (fix in this PR before merging #31) vs follow-up
     (note for next branch, doesn't gate the release)**
   We don't want non-blocking polish fixes ballooning #31 — keep that PR
   scoped to the file-size drain + correctness fixes already in.
6. File-size discipline: any fix must keep allowlist at 0
