# Domios 1.15.1

Release candidate: canonical `rename/domios` 02079ba72 (verified in canonical: Batch5 d7571df31 and Batch6),
real-merged into `release/1.15.1` with the version bump. Publication and tags need the owner's GO.

## What changes for you

- Domios no longer burns CPU scanning lanes: ref changes trigger no lane git work, lanes settle at
  accept, merge or holder close, and each repository has one git queue (P0).
- Background loops converge: no polling of old peers, no nudges to dead Workers, no watches on missing
  repositories and no blocking secret lookups (P0).
- One toast system: every notice goes through the same toasts, including account and update failures.
- `dispatch`, `respawn`, `spawn` and `update` accept `--speed`.
- On macOS, hovering sidebar rows no longer shifts them.
- Updates show per-component progress in a clean panel, and an update that cannot install says why
  before it stops anything. Install refusals reach the CLI with their code and how to recover.
- Plugin installs and updates swap atomically: a failed step rolls back and names the exact step.
- Account, sign-in and update failures appear as toasts instead of a titlebar slot. Small surfaces
  show compact errors; plugin rows take one line with one channel notice.
- Account groundwork: Ledger and Clock ship, Quota ships dormant.
- Attachments appear at once with an uploading state and clearer kind labels.
- A tab previews files in its own AgentPad, with a shared viewport viewer and edge-aware touch previews.
- The sidebar shows each section as `LABEL N` with live working activity and a one-line worker summary.
- Memory Activity lists configured agents, Workers and Services, with details on click.
- Claude model and effort switches apply mid-turn when the provider supports it.
- The tray shows Admin from the server's authority.
- Immediate deliveries skip the queue, heartbeats get their own chip, and the feed never blanks.
- Escape closes the Mesh peer drawer before the view.
- The Browser surface stays stable while the window resizes.

## Fixes

- Runtime launches send only the assigned-task starter; the brief travels as developer instructions (P0).
- Restored tabs bound to their own session no longer show Starting while they work, and interrupted
  tabs and routed messages wake restored tabs.
- Chat runtimes keep their declared agent runtime, and worker failures record their real reason.
- Agent provider listing never waits on a plugin VM.
- Codex edit cards read path-keyed change maps; unknown edits show their raw payload.
- Telegram file sends deliver the document or fail loudly; bridge inject failures stay typed and never replay.
- Agent notifications stay in the bell, with no strip above Chat.
- Updater template placeholders and flag values are never treated as prerequisites; relocation
  tolerates a stray `provider-update.lock`.
- Review hooks do nothing without checklist storage; Workers close seeded criteria by id.
- Retained exit evidence is rechecked when a process identity is lost.
- An isolated verify server opens loopback-only sockets.

## Internals

- Envelope grammar v1 with typed segments and shared fixtures.
- Stage timing instrumentation for providers, chat start, preview and PTY.
- Typed GitHub blueprint node and reuse-first blueprint prompting.
- Release CI runs in tiers that open on claim: fast checks, then Rust tests, then builds, each starting once
  every job of the tier above holds a runner. The tiers live in `tests-fast.yml` and `tests-rust.yml`. Qualified dry runs
  publish through `release-publish.yml`; `RELEASE_AUTO_PROMOTE` stays off.
- The platform test classifier caches results by source digest; platform jobs compile only packages
  with platform-specific tests.
- PR-time script, gateway and frontend workflows are gone: their guards run in release-preflight and
  the fast Linux tier.
- ConPTY shell-exit diagnostics report session, host and shell context.
