### Move from CodeTerm 1.15.1 to Domios 1.15.2

Install Domios fresh by hand, then remove the old application. Do not use
CodeTerm's in-app installer for this release. Data already lives in `~/.domios`
and stays there; no data move, migration script or compatibility shim is needed.
Do not run both applications together.

- **Windows:** quit CodeTerm, including its tray process. Disable its autostart
  in Settings before quitting. Download and run the Domios setup executable;
  the default destination is `%LOCALAPPDATA%\Domios`. Run the old uninstaller
  from `%LOCALAPPDATA%\CodeTerm` (normally `uninstall.exe`); remove only the old
  app, keeping `~/.domios`. Remove any remaining `CodeTerm-Autostart` task in
  Task Scheduler. Launch Domios and re-enable autostart there if wanted. Remove
  old Start-menu/desktop shortcuts and pins, then pin Domios. In a new terminal,
  `where.exe domios` and `where.exe codeterm` must resolve the CLI in
  `%USERPROFILE%\.domios\bin`; the GUI is `domios-app.exe`. Remove old CodeTerm
  directories from the user PATH. Both CLI names run the same installed CLI.
- **macOS:** disable CodeTerm autostart, quit it, then open the Domios DMG and
  install `Domios.app` in `/Applications`. Delete `/Applications/CodeTerm.app`
  and any duplicate old bundle. Remove the old Login Item and unload/remove
  `~/Library/LaunchAgents/com.codeterm.app.plist` if it remains. Launch Domios
  and re-enable autostart if wanted. Remove the old Dock icon and add Domios.
  Open a new terminal: `command -v domios` and `command -v codeterm` must select
  `~/.domios/bin` or the links in `~/.local/bin`, both targeting the current CLI.
  Remove custom PATH entries or links into `CodeTerm.app`.
- **Linux:** disable CodeTerm autostart and quit it. Install the new Domios
  `.deb` (`sudo apt install ./Domios_<version>_<arch>.deb`), RPM, or AppImage.
  Then remove the old `codeterm` package with the same package manager
  (`sudo apt remove codeterm` or `sudo rpm -e codeterm`); for AppImage delete
  the old CodeTerm image and its custom desktop launcher. Disable/remove the
  old `codeterm.service` user unit if still present, then launch Domios and
  re-enable autostart if wanted. In a new terminal, `command -v domios` and
  `command -v codeterm` must select the package-owned `/usr/bin/domios` and
  `/usr/bin/codeterm` CLI commands, or the current CLI links under
  `~/.domios/bin` / `~/.local/bin`. The GUI is `/usr/bin/domios-app`. Remove old
  custom PATH entries, desktop launchers and icons. If the package manager reports a file
  conflict, remove the old package first, then repeat the fresh installation;
  do not force-overwrite package-owned files.

After removing the old app, check autostart, shortcuts, and the default handler
for `domios://` links and any file associations you configured. Set them to
Domios; remove old `codeterm://` associations or custom file handlers. On Linux,
`xdg-mime query default x-scheme-handler/domios` must name the Domios desktop
entry. On Windows check Default apps and Task Scheduler; on macOS check Login
Items and open a `domios://` link. Linux Deb/RPM packages install both CLI
commands in `/usr/bin`. For macOS and AppImage, start Domios once to repair
both CLI links in `~/.local/bin`; verify that directory is already in your shell
PATH, or add it yourself using your shell settings. On Windows first launch
registers `~/.domios/bin` on user PATH. No user shell dotfiles are edited by
Domios. Open a new terminal afterwards. Application data stays in place.

Without the release guard, the 1.15.1 updater would launch a separate Domios
NSIS install on Windows, replace the current bundle in place on macOS (leaving
the old `CodeTerm.app` path with a new identity), or install a differently named
Linux package alongside the old package, conflicting on shared paths such as
`/usr/bin/domios`. An AppImage update replaces the current image while retaining its old filename.
These mixed states are unsupported. New Domios clients use
`domios-latest*.json`; the old `latest*.json` paths publish these manual steps
with **no platform payloads**. The 1.15.1 discovery shows the release notes as
incompatible and cannot offer an install. A forced old install fails at missing
platform selection, before download, shutdown or installation; the old binary
cannot gain a new custom error dialog from release metadata.

The bundle identifier changes to `com.domios.app`. macOS treats Domios as a new
app for TCC permissions, including microphone and Accessibility: grant access
again when requested, or enable Domios in System Settings → Privacy & Security.
Old Keychain items may prompt for access by the newly signed app; approve the
prompt or sign in again if access is denied. No Keychain ACL is silently copied.
Windows notification identity/AUMID and notification preferences are new too;
allow notifications for Domios again. Existing denial/fallback and permission
request paths remain available; the old app's OS grants are not inherited.
