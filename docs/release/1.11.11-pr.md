## CodeTerm 1.11.11

Plan `pl_kgxkj2`: a broad exploratory QA campaign on dev, followed by fixes for every finding and a live cross-provider delivery matrix (Claude, Codex, OpenCode) on Windows before this PR.

### Message delivery (owner-approved PTY changes)
- A message never stays unsubmitted in an agent's composer. The turn state is captured before the paste, so the paste's own echo no longer reads as an active turn. When a paste lands mid-turn, the first submit key waits for the turn-end, idle or composer-ready event. Every Idle source, including the idle poll, wakes that wait. If the draft is still there at the deadline and no dialog is visible, the bounded key schedule runs.
- Automatic submit keys never go into a provider dialog. Plain text sent to a tab showing a trust, update or choice dialog is refused before any write (`tab_busy_refused`, `bytes_written:false`), and the dialog check reads the current frame. Every delivery wait has a bounded deadline.
- Long messages to Claude are taken as the sender's request. Claude Code wraps pastes of 5+ lines as pasted content, and heavy sessions refused to act on them. A provider capability now adds one short typed follow-up line after such a paste. Live result: 0 of 54 refusals in a heavy Sonnet session (was 15 of 15), and the follow-up appears exactly once per long message, never on short messages, Codex or OpenCode.

### Reliability and security
- crash-1351: provider-controlled file reads are bounded. The dev OOM came from a whole-file read of a live 2.36 GB SQLite database. A missing plugin file again reads as `null`.
- Machine-global provider writes are isolated; plugin ids and skill slugs are constrained; provider task files are owned per instance.
- Mesh: introductions require approval; isolated peers are scoped to the tabs they own; relayed requests enforce tab ownership; CLI results are truthful.
- Cron: owner routing, run lifecycle and history for oneshot jobs, schedule validation, workspace cleanup, secured run watching.
- Config: writes are refused while the config is held; a salvaged config stays readable; corrupt state files are preserved, not replaced; input text is bounded.
- Session restore:
  - Windows restarts dispatch as plain shell lines;
  - exit recovery keeps verified bindings;
  - the OpenCode lifecycle is repaired across restarts;
  - declared stop sequences are honored.
- Worker loss is pushed to the Orchestrator; busy Team close is refused; spawn fails loudly on dead launches and bad cwd; the CLI `--json` contract holds on every path.
- Memory: skill delete tombstones, one id per skill folder, versioned same-title saves, capped flush bodies, fair embedding schedule.

### Test tooling
- Rust test runs are capped by default: 600 s focused, 3600 s per suite, `TEST_CAP_SECS=0` disables the cap. Compilation runs outside the cap. On a cap hit the run exits 124 and names each still-running test with its duration. PTY test fixtures use bounded waits, so a hung test fails instead of stalling a gate for an hour.
