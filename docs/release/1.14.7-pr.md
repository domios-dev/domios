# Domios 1.14.7

Plan `pl_xq9cj4`. Codex moves to the Chat-only agent runtime and into the `provider-codex` plugin.

## Fixed
- Codex runs on the stdio app-server runtime with no PTY: start, resume, history (with a `thread/read` fallback for Codex 0.160), sends, approvals and questions, interrupt with completion wait, model, effort and mode controls (CLI, self and cross-tab), usage.
- Codex sign-in without a PTY: browser (system browser), device code, API key over stdin or a masked field, terminal fallback; the same thread resumes without restart.
- The role identity of every role (Orchestrator, Planner, Worker, General, cron, memory workers, dreamer) is composed into the runtime system prompt and refreshed on resume and after compaction.
- Legacy PTY Codex tabs migrate to the runtime on restore; plan task dispatch, cron and memory workers, agent restart (resume and fresh) and tab stop work on runtime tabs.
- Unmapped provider server requests get correlated error replies; human-readable runtime errors; compact one-row Chat status banner.
- Account tray with provider and action icons.
- Release pipeline: independent per-artifact jobs and runner labels, structural bundle smoke checks, signature verification before publish, serialized publication, dry runs include tests.
- Gate and dev reports alert the Orchestrator on the first failure.
- Test isolation: no unit test reads the machine config or the shared lifecycle journal; platform-scoped recording tests; subsecond closed-tab cap tests.
