Plan `pl_blazzd`. 1.12.1 was tagged but never published (its release bundles did not build), so 1.12.2 ships everything in 1.12.1 plus the changes below. The 1.12.1 notes follow the 1.12.2 section unchanged.

### Memory: Supporter Agent
- Settings > Agents has a Supporter Agent block: the decision token field, its status, and a link to the Guide.
- Settings > Guide has a Supporter Agent section. It explains what the TypeSafe Jev decision model does, what is sent to it, what it costs, and what happens on fallback.

### Dreamer
- Dream runs no longer improvise scripts. Approval prompts used to park hidden runs for 30 minutes.
- `mem graph hubs --limit` returns hubs with clusters computed in Rust.
- REM uses a staged prompt (281 lines).
- The host finalizes a run on its deadline or on an approval prompt, so no diary is left INCOMPLETE.
- `mem merge` is reversible and replaces hard delete; `mem restore` reverses archives.
- `mem calibration stale --dry-run` previews the stale archive. The stale archive is off by default.

### UI
- Dream cards are centered and show a one-line run summary.
- Memory graph edges are nearly transparent until a node is selected (premultiplied colors), and the graph refreshes when it is opened.
- Plans: incoming plan text refuses only control characters (PR `#521`), and Spec, Plan and Tasks stay selectable without a matching plan (PR `#522`).
- Web: the machine picker lives in the titlebar and stays reachable when a peer's state is empty, collapsed, compact, pending or failed (PR `#523`).
- Web: after switching to another mesh peer, Board, Spec, Plan, Tasks and the sidebar plan rows load that peer's plans; plan calls go through the selected-peer relay, a peer switch clears the previous machine's snapshots, and event replay cursors are scoped per peer (PR `#524`).

### Orchestration and plugins
- Stalled-Team nudge: the Orchestrator gets one reminder when actionable work has no live Worker.
- The core plugin channel now appears in `plugin channel diff` and `plugin channel refresh`; it used to report "not registered".

### Windows
- The decision token file gets a current-user-only DACL, and `mode_ok` reports it truthfully.

### Release
- Release bundles build again: the bench module moved out of `src/bin`, and `build.ps1` parameters are named-only.

### Measured and kept off
- Hybrid docs vectors: R@1 equal, +136 ms.
- Sessions source: 0 hits, +513 ms.
- Tab-state shadow: there are no labelled boot or error-loop screens yet.

### Embedded docs
- `codeterm docs` pages now carry only what an agent needs to operate CodeTerm. PROMPTS, PROMPT-TIERS and PROMPT-DETECTION left the binary, and the source internals of 25 other pages (module layout, SQL schema, ranking formulas, scheduler and parser mechanics, UI component names, source paths) moved to internal references under `.agents/skills`.
- Corrected on the way: the Dreamer recipe no longer says to delete duplicates (it merges reversibly), and the dictation guide drops a synthetic-keystroke workaround in favour of the tab send API.

## CodeTerm 1.12.1

Plan `pl_blazzd`, Team MemRerank: an optional, model-agnostic decision re-rank for memory recall, measured on a copy of real memory before any default was set. Everything new is off unless enabled. With it off, recall output is byte-identical to 1.11.11.

### Memory: decision re-rank (new, off by default)
- An optional second stage for `mem search`. A fast decision model scores each recall candidate with one question: does this memory directly and usefully answer the query? The candidates are then re-ordered. The interface is model-agnostic (`DecisionModel` capability registry); the first adapter is TypeSafe Jev, native.
- It never filters. The caller gets the usual number of results, re-ordered, and each hit carries `relevance`. `low_confidence` is only a flag, raised when even the best candidate looks unlikely to answer.
- Safe by default: `[memory.decision_rerank] enabled = false`. With no token, a timeout (one 3 s deadline), an error, or an unregistered adapter, the hits are exactly the plain recall hits, plus a fallback reason. A partially judged pool is never returned.
- Access accounting is unchanged. Candidates are read without touching `access_count`, and only the returned memory hits record one access each.
- Optional candidate sources share the same pool. Each adds candidates only when re-rank is applied, never in fallback, and never mutates memory:
  - graph-linked memories (`sources.graph`, default 3);
  - embedded CodeTerm docs plus the generated CLI command reference (`sources.docs`, default 3), each hit with a `codeterm docs NAME` pointer;
  - past sessions (`sources.sessions`), present but off (default 0): it found no hits in measurement and stays off in 1.12.2 (see above).
- The token is stored locally per adapter: 0600 on Unix, in the instance data directory, outside the vault. It is entered only through stdin (`codeterm mem secret get --name typesafe-jev-api-key | codeterm mem decision token set`) or the masked settings field, and never logged or printed.
- Surfaces:
  - `mem search --decision-rerank on|off`;
  - `mem decision token set|clear|status` and `mem decision status`;
  - Memory > Settings > Decision re-rank card;
  - Settings > Guide > Decision re-rank;
  - `/api/mem/decision/*`.

### Measured on a private copy of real memory (456 items; 80 paraphrased questions)

|---|---:|---:|---:|---:|
| cosine (today) | 0.145 | 0.184 | — | 0.39 s |

- Doc how-to probes: the right doc section is first in 4–5 of 8 with docs on, 0 of 8 without.
- The "nothing relevant" gate at 0.15 has precision 0.76 and recall 0.76–0.80.
- The wording ("directly and usefully answers" rather than "relevant to") was chosen by a live A/B against the owner's prototype.
- Measured and not shipped: an automatic hint on CLI usage errors (hit@1 46.7%, 3 of 15 confident-wrong, gate failed), and past-session candidates (0 hits, +250 ms).

### Fixes
- A reused, live, session-bound General Agent no longer stays at `ShellReady`, so mesh sends to it are no longer refused as "still launching". The existing authenticated-binding reconciliation now also runs on the already-running path (owner-approved).
- Heuristic "Agent needs your response" notifications are removed. Prompt detection still works (`tab respond`, launch readiness), and escalation goes through `codeterm notify send` only.
- `codeterm agent restart --mesh` restarts the named peer tab. Every other agent verb over mesh is either mapped or refused clearly, where before it silently listed tabs.
- The Codex resume command refuses a Codex CLI without `--no-daemon`, with an upgrade instruction (PR `#517`).
- Settings toggles: the knob fits its track again and uses the foreground color.
- Memory extraction: conflicting facts are linked with `supersedes`, and startup no longer resumes extraction when `memory.auto_extract` is off.

### Tooling
- `./build.sh dev --wait --notify-tab <tab>` reports READY or the failure stage to the calling tab through the parent CodeTerm. `scripts/qa-report.sh` runs gates with pipefail and a zero-tests guard, and reports a summary to a tab. Skill: `.agents/skills/utility-shell-reports`.
- `./build.sh check-tests` compiles every workspace member's test targets.
- CI actions move to their Node 24 majors (`actions/checkout@v5`, `actions/setup-node@v5`).
- TS unit and vitest workers start with `--no-experimental-webstorage` where Node supports it, so local Node 25 sees the same storage globals as CI's Node 22.
- Three pre-existing parallel test races are fixed: live model-catalogue fixtures share no provider id, and OpenCode resume parity tests take the env lock.
