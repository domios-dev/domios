## CodeTerm 1.12.3

Plan `pl_blazzd`. 1.12.3 brings the Supporter Agent to every surface, moves decision models into the plugin SDK, and ships the tab-state observer in observe-only mode.

### Supporter Agent everywhere
- `codeterm supporter enable|disable|status|use|features|token`, one `[supporter]` config section, and `/api/supporter`.
- Settings has a Supporter Agent card with the overall state, the model and per-feature toggles.
- The Guide section is redesigned: plain language, two diagrams, and a link back to Settings.
- **Breaking:** `mem decision` and `[memory.decision_rerank]` are gone. After updating, set the token again (`... | codeterm supporter token set`) and run `codeterm supporter enable`.

### Memory
- `mem search --json` returns compact hits (id or doc pointer, source, scores).
- Memory > List search no longer calls the decision model.
- `mem archive` is a reversible single-item archive.

### Decision models as a plugin capability
- `decisionModel` is a capability in the plugin SDK.
- `host.fetch.async` releases the plugin VM while the request is in flight.
- Unknown manifest capabilities are ignored instead of refusing the plugin.
- Git channel calls never prompt for credentials.

### Tab-state observer
- Context header, confidence bands, two-observation persistence, the hidden-worker PATH fix and folder-trust fail-fast.
- Ships observe-only (actions off) after the e2e oracle; actions come in 1.12.4.

### Cron
- Cron runs are judged only after their own launch (issue `#529`).
- A hidden cron launch waits for the shell to be ready.

### Plans and routing
- Stored plans are bounded by bytes, not by text field count (PR `#528`).
- Plan lifecycle commands forward the caller binding (issue `#518`, PR `#525`).
- `send --require-agent` resolves the `main` and `general` aliases to the General Agent (issue `#497`).

### Essences
- Supporter Agent and memory hygiene contracts.

### Measured and deferred
- LM Studio decision adapter: deferred to 1.12.4.

### Verification
- `release-credentials.yml` on master, one `./build.sh release-preflight` on the release head, a `release.yml` dry run on `release/1.12.3`, and the tests.yml matrix on this PR, including the Windows tab-state, run-watcher, cron and token DACL tests.
