## Domios 1.14.2

Plan `pl_fni7jw`. 1.14.2 moves the desktop onto the same HTTP and SSE transport as the web UI, ships signed frontend bundles that can update without an app release, and hardens restore and message delivery for every agent provider. It is the last release before the public release.

### One transport
- The desktop window uses the same HTTP and SSE API as the web UI; Tauri is a thin shell (issue `#567`, lanes 1–6).
- One events stream and one output stream per page, so WebKit no longer stalls on shared SSE (issue `#572`).
- Provider icons and Chat transcripts load over HTTP in the desktop window (issue `#573`); the four frontend commands without a daemon implementation are implemented (issue `#569`).
- The configured Vite frontend boots in WebKit (issue `#577`); provider Settings install actions keep their provider id in the browser transport (issue `#585`).

### Signed frontend releases
- The daemon serves signed frontend bundles with a silent swap and automatic rollback, and accepts only a release newer than its own frontend and the active bundle. A healthy swap reports its health across origins (issue `#610`).
- A separate `frontend-release.yml` pipeline builds, signs (dedicated minisign key) and publishes `frontend-vX.Y.Z` releases without an app build. The first frontend release, `frontend-v1.14.2`, follows this release.

### Restore and delivery
- Codex agents resume after a Domios restart: session binding, sidecar fallback and the owed continue (issues `#557`, `#555`).
- Restored OpenCode tabs deliver their first message, and fresh ones leave Starting (issue `#563`).
- A send held during a slow launch survives the launch and is delivered once, in order, to the same session; a changed session ends it honestly with Retry (issue `#590`).
- A fresh restart while a restored tab is starting settles that launch's held sends as not delivered with Retry, and never carries them to the old session (issue `#599`). A forced fresh restart waits for observed process-tree termination instead of console cleanup, so it no longer fails on Windows (issue `#598`).
- App restart works again: the successor waits for the instance lifetime lock instead of exiting (issue `#597`), and it never inherits its launcher's stdio, so a closed pipe can no longer crash its logger or poison PTY creation (issue `#605`).
- A send right after session binding is held instead of refused, and the CLI exits nonzero on refusal (issue `#578`); a model Apply command no longer merges into a concurrent chat message (issue `#586`).
- Routed frames are pasted whole (issue `#563`); a numbered list inside a delivered message is no longer reported as an agent prompt (issue `#570`); long Chat sends to Claude are fast again (issue `#541`).

### Providers
- Provider CLIs update silently in the background (issue `#556`).
- OpenCode 1.19 Chat is trusted (issue `#561`); OpenCode offers only models it can run, with stable labels (issue `#564`); a 410 model error is surfaced instead of a silent idle tab (issue `#582`).
- A structured-control Codex turn shows Working in the status API (issue `#587`); the Codex reasoning submenu is classified and answered safely (issues `#579`, `#583`); completed Opus turns emit Idle on shared SSE (issue `#575`).
- Aider launches as a Worker and receives sent text without bracketed-paste markers (issues `#540`, `#549`).
- Grok's catalogue is live, and mesh dispatch validates models against the target peer (issue `#546`).
- Rotterdom, a lightweight router and harness plugin for local and OpenAI-compatible models (issue `#566`).
- The Browser core bundle installs and loads automatically (issue `#554`).

### Chat and UI
- iPhone and iPad web Chat: overflow, keyboard insets, inline images, upload errors, stale delayed sends and Enter to send (issues `#543`, `#548`); the phone UX audit U01–U13 (`#560`), and a plain-text desktop paste no longer pops the WebView Paste button (U14).
- Chat renders legacy `@ct-` image, page and document directives as previews, and the Browser screenshot hint names `@ds-image` (issue `#607`).
- Live Chat keeps assistant evidence and bottom anchoring while streaming, and every web page keeps its own tab (issue `#584`).
- Action-needed questions are compact and disappear once superseded (issue `#551`); every message shows its send time on hover (issue `#562`).
- Plugin views render in WebKit and the desktop window: plugin frames allow inline styles while scripts stay nonce-bound (issue `#609`). The OpenCode logo renders as its hollow mark (issue `#613`).
- A default agent icon replaces missing provider logos (issue `#574`); the lone clock icon is gone from the composer (issue `#576`); the sidebar hover overlay no longer covers Browser and Probe rows (issue `#568`).
- Chat mounts only the visible window and budgets highlighting, cutting renderer memory (issue `#559`).

### Plans, Workers and Blueprints
- Blueprints show a run counter per unchanged state and honour `--every` (issue `#539`).
- An adopted agent is listed as an agent, not a utility shell (issue `#553`); a fresh task-bound Worker gets `CODETERM_ATTEMPT_ID` in GUI-PATH mode (issue `#581`); respawning a non-repository task skips lane verification outside git (issue `#580`).
- Spinal Cord reflexes rerank in one call and the heartbeat asks every 30–40 minutes (issues `#558`, `#565`).

### Windows first run
- On a fresh Windows install with the default Restricted PowerShell policy, shell integration loads without an error in every tab, the Install action no longer fails on a long prerequisite hint, and a blocked installer says why and how the user can allow it (issue `#614`).

### Build, update and tests
- `update install --from-file` no longer leaks `CODETERM_*` into the relaunched app (issue `#544`); the Debian updater queries the installed package (issue `#552`).
- Grown build times investigated and cut: packaging 135 s instead of 241 s (issue `#545`).
- The REST API restart exits nonzero on failure, with two-listener coverage (issue `#596`, not a regression: both listeners are served).
- The chat harness ignores manual pre-send samples (issue `#588`); the ChatMessageSelection menu test is stable (issue `#589`).

### Investigated, not fixed
- `#591` scoped meshqa startup port and `#594` dev-prebuilt provenance are DEV tooling, not product.
- `#571` mobileqa Vite reachability during acceptance is DEV tooling.

### Deferred, with reasons
- `#608` General Agent launch stays failed when frontend readiness arrives after its deadline: the trigger seen is DEV-only (Vite not serving at navigation); the retry gap goes to the next train.
- `#550` Blueprint execution verification and GitHub watcher recipes: feature work for the next train.

### Verification
- `release-credentials.yml`, one `./build.sh release-preflight` on the release head, and the tests.yml matrix on this PR.
- Live restore on macOS (Claude, Codex, OpenCode, Aider; normal and GUI PATH) and Windows (Codex, OpenCode): idle restore, Working restore with exactly one continue, held sends delivered once, first message after restart.
