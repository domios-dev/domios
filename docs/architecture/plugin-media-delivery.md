# Plugin media delivery

The shared desktop/web iframe loader previously allowed only blob/data images and fonts. It had no media-src or media capability. This adds a bounded host delivery capability without network or arbitrary filesystem grants.

A view declares `capabilities.mediaDelivery: {types: ["video/mp4", "image/png"]}`. Its backend looks up an already-produced file (never starts paid work) with `mediaFile(id, context) -> {path, contentType, fileName?}`. The relative path is interpreted only inside the host-selected plugin data directory. The iframe calls `ct.media(id)` and receives `{handle, url, content_type, file_name, expires_in_seconds}`. It never supplies or receives a filesystem path. PNG, JPEG, WebP and GIF images passing the bounded header check receive the same scoped preview URL. Images that cannot be safely previewed retain gesture handles with a null URL. SVG/HTML are never admitted.

Only the authenticated local owner document loader can create a frame, register a backend result, or revoke a frame. Playback GET/HEAD self-authenticates with an exact opaque plugin/frame/handle path. The owner bearer credential never appears in playback URLs or document markup. Other routes retain bearer authentication. The existing exact-origin CORS policy exposes the frame header alongside CSP for desktop and web loaders; it grants no new origins. The common loader adds only this frame's exact absolute media route prefix to img-src alongside its existing blob/data sources, and to media-src alongside blob playback; connect-src stays none. Frame bridge messages must come from the current iframe, and asynchronous completions recheck that identity.

Frames expire after 30 minutes and handles after 10 minutes (bounded by frame lifetime). Limits are 128 frames globally, 16 per plugin, 16 handles per frame, and 256 MiB per file. Expiration is checked on every operation and stream chunk; stale entries are reclaimed on the next document/provider access. Document replacement, close, or in-frame reload revokes the frame. Plugin reload/unload revokes every plugin frame. A missing cleanup request therefore remains bounded by expiry and store caps. Source files remain plugin-owned and are never deleted by handle cleanup.

Registration opens the plugin root and every child without following symlinks/reparse points, verifies a regular nonempty file, size, passive MIME and container signature, and sanitizes the display filename with a passive extension. Playback retains that open file and reads in at most 64 KiB blocks with explicit offsets under one cursor lock; it never reopens the path. Gesture consumers use `open_frame_media(plugin, frame, handle)`, which checks exact-frame ownership and repeats the same confined open/format/size validation. Returned paths are for explicit reveal only. File contents remain mutable by the owning plugin; a handle is delivery authority, not a content digest or archival guarantee.

Image previews are capped at 32 MiB encoded, 8192 pixels per side and 16 megapixels in the declared canvas. PNG IHDR, GIF logical screen, 8-bit baseline/extended/progressive JPEG SOF and WebP VP8/VP8L/VP8X dimensions are parsed from at most 256 KiB of headers without decoding pixels. Unknown/truncated headers, unsupported JPEG variants and oversized metadata or dimensions yield no preview. Admission rechecks the retained file header before GET/HEAD and retains that bounded header for the response, so in-place producer writes cannot change the delivered dimension declaration after validation. Remaining bytes stream from the retained file; file I/O runs on a blocking worker. These resource bounds do not make mutable producer bytes an archival snapshot or guarantee a browser decoder's total animation memory.

Only single RFC byte ranges are supported. Full, suffix, bounded and open-ended ranges work; multiple, malformed, oversized, overflowing and unsatisfiable ranges return 416 after authorization. HEAD returns the same headers without reading a body. Responses use a finite MIME allowlist, nosniff, no-store and Accept-Ranges. Unknown, foreign and expired playback capabilities produce the same 404 without media metadata.

The native ViewProvider and JS mediaFile export share one descriptor and file model, with parity fixtures. `open_owned_media` reuses validation for host-stamped producer plugins but conveys no Team, workspace or run authority. Durable Blueprint references and authorized cross-plugin handoff belong to the execution layer; they must not persist a frame token or claim that a mutable plugin source is an immutable artifact.

Canonical validation: plugin/service/API lane-check with tests; plugin nextest selectors `media_delivery` and existing code-source fixtures; API nextest `plugin_media_routes` and `web_plugin_routes`; Vitest pluginDocument and PluginView.activation; fmt, file-size/layering/API-effect guards. Worker authored fixtures only; no executions performed.
