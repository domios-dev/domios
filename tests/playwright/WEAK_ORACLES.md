## Not covered at the Playwright layer

| Surface | Why the Playwright layer cannot assert it | Where it is covered instead |
| --- | --- | --- |
| Child tab reordering within a parent group (`18-reorder/reorder.spec.ts`, removed C2) | The Playwright layer cannot construct a parent/child tab pair without a live agent. `parent_tab_id` is settable only through `POST /tabs/{id}/role` or `POST /tabs/{id}/make-orchestrator`, both of which transition with `require_verified_session: true` and answer `400 agent_unavailable` for a tab that never reported a session binding, or through `POST /agents/spawn`, which spawns a real provider agent — and the `golden` project grep-inverts `@stub`. The UI handle is gone as well: only `tab:<workspaceId>` and `workspace:workspaces` dnd groups render, so `child:<parentTabId>` cannot be dragged. | `src-tauri/crates/codeterm-pty/src/multiplexer/state/reorder.rs`: `reorder_children_orders_only_same_parent_siblings`, `reorder_children_rejects_foreign_parent`, `reorder_tabs_rejects_a_child_tab`. |
| The first-run BOOT path — a daemon that has never been configured minting the picker tab (`21-first-run/first-run.spec.ts` covers the surface, not the boot) | The picker tab is created only inside `startup/states.rs`, at boot, and only when three preconditions hold together: `general_agent.enabled`, `general_agent.first_run_complete == false`, and a restored mux state with **no** protected workspace holding a protected tab. That third one is the blocker. `snapshot_has_protected_main` runs first and, when it sees one, force-sets `first_run_complete = true` **and persists it** — so on any instance that has ever had a General workspace, writing the config key back to `false` is silently undone at the next boot. Reaching the state therefore requires discarding the instance's session snapshot, which destroys every workspace and tab the rest of the suite is standing on. It cannot be restored afterwards either: teardown would have to re-import a snapshot the daemon has already re-persisted. `21-first-run` instead asserts the surface the boot path produces — a tab carrying `FIRST_RUN_TAB_MARKER`, created through `POST /tabs` — read from the Rust constant so a rename on either side fails the spec. **Cheapest honest shape for the boot leg**: one dedicated named instance (`CT_E2E_INSTANCE=firstrun`, its own `~/.codeterm-dev-firstrun`, `CARGO_TARGET_DIR` shared so the build stays warm), prepared and booted by a driver outside Playwright, handed in by env — the `10-restore/restore-matrix.spec.ts` pattern. **One boot serves the entire flow**: picker present → provider chosen → `complete_first_run_core` → General workspace + protected tab + bound session, all as one linear test. It is one standup for the whole first-run story, and it never touches the golden instance. | `src-tauri/src/service/general_agent/first_run.rs` unit tests: `needs_picker_when_enabled_and_incomplete`, `ensure_first_run_tab_creates_marker_tab`, `ensure_first_run_tab_is_idempotent`, `first_run_sole_picker_workspace_and_tab_are_protected_against_empty_close`, `first_run_picker_not_protected_when_other_workspaces_exist`, `first_run_picker_tab_has_skip_snapshot_set`, `ghost_repro_first_run_picker_excluded_from_snapshot`. |
| Confirming the first-run picker (`agent-picker-confirm` → `complete_general_agent_first_run`) | Clicking confirm rewrites `general_agent.agent_provider`, `general_agent.first_run_complete` and `agent.full_access` in the shared instance's `config.toml`, clears the persisted General-agent session id, closes every marker tab and relaunches the General Agent. None of that is per-test state and none of it is restorable from inside a spec, so `21-first-run` asserts the picker is *confirmable* (an installed provider preselected, the button enabled) and stops there. The click belongs to the dedicated-instance shape in the row above. | `src-tauri/src/service/general_agent/first_run.rs::close_first_run_tabs_retires_the_protected_picker`; `workspace.rs` `ensure_general_workspace` unit tests for the post-confirm workspace shape. |
| Which providers the first-run picker shows as *installed* | `useProviderAvailability` resolves install state through the Tauri command `check_cli_installed`, which has **no REST mirror**: `src/lib/bridge.ts` lists it under `CANNED` and answers a hardcoded `true` in web mode. A spec therefore cannot derive the expected installed/disabled split from backend state on either transport. `21-first-run` asserts only what is derivable: one card per `transport === "pty"` provider from `/agents/providers`, exactly one preselected, and that the preselected card reports `data-installed="yes"` — reading the split off the product's own attributes rather than predicting it. | Not covered elsewhere. A REST mirror for `check_cli_installed` is the missing handle. |
