⏺ The fuzz harness is clearly broken (it reports even no-op combos like Up+Up as deaths — impossible in one tick
  mid-board), so I'm discarding it. The direct positional capture is authoritative, and it shows two important things:
  - A single opposite press (Left while moving right) is already correctly ignored — head went 9,10→10,10→11,10, snake
  stayed alive. So there is no direct 180° reversal bug; changeDir blocks it.
  - But Up+Left in one tick made the snake turn up and silently drop the Left.
  The cause
  The real defect is in how queued turns are validated. changeDir validates each new direction against the committed
  direction dir and stores only one pending turn (nextDir):
  function changeDir(x, y) {
    if (x === -dir.x && y === -dir.y) return;  // checks the CURRENT facing
    nextDir = { x, y };                         // single slot, overwritten
  }
  Because the snake only takes one step per tick but the game runs many animation frames per tick, a player rounding a
  corner naturally presses two keys within one tick (e.g. moving right: Up then Left). The Left is validated against the
  still-committed dir (right), where it reads as a reversal, so it's thrown away — even though after the Up step it
  would be a perfectly legal turn. The intended quick corner gets lost, the snake keeps going straight into the
  wall/itself, and it feels like the controls reversed/betrayed you.
  The fix is a small input queue: validate each press against the last pending direction (not the stale committed one),
  buffer up to two, and apply one per tick. This honors fast corner turns and makes a 180° reversal impossible by
  construction.
